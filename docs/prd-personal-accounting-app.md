# 产品需求文档：个人记账应用

## 问题陈述

个人用户需要一个简单易用的记账应用来管理财务。现有记账应用要么功能过于复杂，要么缺乏智能化功能。用户需要一个纯本地存储、具有AI智能分类的轻量级记账解决方案。

## 解决方案

开发一个基于Tauri 2.0的个人记账应用，仅支持Android平台。应用提供以下核心功能：
- 基础记账功能（收入/支出记录、分类管理、账单查询）
- 预算管理（月度预算、分类预算、超支提醒）
- 报表分析（收支统计、趋势分析、图表展示）
- AI智能分类（用户自配LLM API，异步分类）
- 数据备份与恢复（JSON格式导出/导入）

### 技术栈
- **前端**：React + Tauri 2.0（Android）
- **本地数据库**：SQLite
- **设计系统**：参考CLAUDE-DESIGN.md风格，创建独立的记账应用设计系统
- **语言**：仅支持中文
- **货币**：默认人民币（CNY），应用内固定单一货币，不支持多币种切换

### Android兼容性
- 最低支持版本：Android 8.0（API 26）
- 目标版本：Android 13/14

## 实现决策

### 技术架构
- **前端**：React与Tauri 2.0用于Android部署
- **本地数据库**：SQLite用于本地存储
- **业务逻辑**：Rust层在Tauri进程内处理所有逻辑
- **AI集成**：用户自配LLM API密钥，异步分类

### 权限管理
- **INTERNET**：必需权限，用于调用用户自配的LLM API进行AI分类
- **POST_NOTIFICATIONS**（Android 13+）：可选权限，用于预算超支本地通知

#### 通知权限申请流程
1. 首次触发超支提醒时弹出系统权限申请对话框
2. **用户授权**：正常显示本地通知
3. **用户拒绝**：降级为应用内提示
   - 打开应用时在首页顶部显示横幅警告（"您有预算即将超支"）
   - 进入预算页面时显示内联警告卡片
   - 不再重复请求权限，用户可在设置中手动开启

### 模块设计
1. **交易模块**：核心记录功能，支持CRUD操作、搜索和定期交易
2. **分类管理模块**：预定义和自定义分类，包含图标和组织功能
3. **预算管理模块**：月度和分类预算，支持跟踪和超支提醒（80%黄色警告，100%本地通知）
4. **报表模块**：统计分析，使用ECharts图表（折线图、饼图）
5. **AI分类模块**：用户自配LLM API，异步分类，离线时降级到未分类
6. **备份模块**：JSON格式导出/导入，支持日期范围选择，导入时采用覆盖策略（全量覆盖本地数据）
7. **设置模块**：通知设置和应用配置

### 数据库模式（关键表）
- `transactions`：收入和支出记录
- `categories`：交易分类
- `budgets`：预算设置和跟踪
- `recurring_transactions`：定期交易配置

### 数据备份与导入
- **导出格式**：JSON文件，包含所有表数据及元数据（导出时间、版本号）
- **导出交互**：利用 Android 原生分享机制（Share Sheet），Tauri 调用原生分享将生成的 JSON 文件流传给系统，由用户自行选择保存位置（微信、文件管理器、云盘等），无需申请存储权限
- **导入交互**：通过 Android 文件选择器（File Picker）让用户选取备份文件，无需存储权限
- **导入策略**：全量覆盖模式
  - 导入前提示用户确认（"导入将覆盖当前所有数据，是否继续？"）
  - 导入时先清空本地所有表数据，再写入备份文件中的数据
  - 导入失败时回滚到导入前状态（事务保证原子性）
- **备份文件结构**：
  ```json
  {
    "version": "1.0",
    "exported_at": "2026-06-01T12:00:00Z",
    "data": {
      "transactions": [...],
      "categories": [...],
      "budgets": [...],
      "recurring_transactions": [...]
    }
  }
  ```

### AI集成
- 用户自己配置LLM API密钥，使用Android KeyStore加密存储在本地
- 异步分类：记账后后台调用API
- 输入：交易描述、金额、日期，以及当前用户所有分类列表（预定义 + 自定义）
- 输出：建议的分类（必须且只能从给定的分类列表中选择，不得自行发明新分类）
- Prompt 强约束："从以下分类列表中选一个最匹配的分类返回，仅返回分类名称，不要额外文字。分类列表：[...]"
- 离线或API调用超时（10秒）时降级到未分类
- 用户可修改AI分类结果

### 设计系统
- 参考CLAUDE-DESIGN.md风格（温暖奶油色画布、珊瑚色强调色）
- 创建独立的记账应用设计系统
- 仅支持中文
- 响应式设计，适配Android各种屏幕尺寸

### 定期交易
- 应用启动时，以及应用从后台恢复到前台时，检查并创建到期的定期交易
- 支持设置重复周期（每周/每月/每年）

### 错误恢复
- 记账时自动保存草稿（每30秒）
- 提供"清除数据"选项

### 用户引导
- 简单欢迎页面（1-2页）
- 空状态引导提示（如"还没有交易，点击+添加"）

## 进一步说明

### 开发阶段（按依赖关系排序）
1. **阶段1**：核心功能（基础交易、分类）
2. **阶段2**：预算 + 报表（高级功能）
3. **阶段3**：AI分类 + 导出 + 优化（完善功能）

### 设计原则
- **简单性**：打开即用，无需注册登录
- **智能性**：节省时间的AI智能功能
- **隐私性**：数据完全本地存储，不上传云端
- **轻量性**：纯本地应用，无后端依赖

### 成功指标
- 交易录入频率
- AI分类准确性
- 用户满意度评分

### 风险与缓解措施
1. **LLM API可用性**：离线时降级到手动分类，用户自配API密钥
2. **数据隐私**：数据完全本地存储，API密钥加密保存
3. **性能**：利用 SQLite 索引优化查询，通过分页加载（每页30条）确保历史账单流式渲染的流畅性
4. **用户采用**：专注于直观设计和入门引导
